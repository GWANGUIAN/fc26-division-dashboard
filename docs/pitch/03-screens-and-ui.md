# 03. 화면과 UI — 로딩, 피치, 캐릭터 선택, 락커룸, 스탯 육각형

> 좌표는 **논리 960×540**, 좌상단 원점, 단위 px. 모든 화면은 캔버스에 그리며 텍스트는 **Galmuri11**로 캔버스에서 렌더한다(이미지에 글자 없음, [05](05-art-world-and-ui.md)). 게임 규칙은 [02](02-gameplay-spec.md), 구조는 [01](01-concept-and-architecture.md).

## 0. 공통

- **z-order(위→아래)**: 토스트 > 모달/오버레이 > 전환 와이프 > HUD > 이펙트 > 스프라이트(y 정렬) > 골 앞 네트 > 배경.
- **항상 보이는 요소**(로딩 제외 전 씬): 우상단 **대시보드 버튼**. 오버레이(선택창·스탯) 중에도 표시한다.
- **버튼 상태**: normal / hover(커서 손가락 + 밝은 시안 글로우) / pressed(2px 눌림). 키보드 포커스는 골드 아웃라인. 클릭 소리 `pitch-ui-click`, hover `pitch-ui-hover`([06](06-audio.md)).
- 텍스트 색: 기본 `#f7f7ff`, 강조 골드 `#ffd23f`, 경고 코랄 `#ff4d6d`, LED 앰버 `#ffb400`, 그림자 1px 네이비 `#0a0a1a`.
- 폰트 크기: 본문 12, 라벨 10, 버튼 12, 제목 20~32(정수 픽셀만).
- **소리 크기 패널(`ui/volumePanel.ts`, 피치·락커룸·스탯 화면 공통)**: 소리 버튼(684,20,40×40) 클릭 = 기존처럼 음소거 토글. 버튼이나 패널 위에 마우스를 올리면 (540,66) 184×92 패널이 열리고(도형으로 그림, 이미지 없음) `효과음`·`배경음` 슬라이더(트랙 80px, 5% 단위, 드래그·클릭, 캔버스 밖으로 나가도 `setPointerCapture` 로 계속)와 `-`/`=` 키(둘 다 ±10%, 1.4s 동안 패널 표시)로 `sfxVolume`/`musicVolume` 를 저장·즉시 적용한다. 슬라이더를 올리면 꺼져 있던 채널이 다시 켜지고, 0% 는 음소거가 아니라 볼륨 0 이다. 효과음 슬라이더를 놓으면 `ui-click` 으로 미리듣기. 패널이 열려 있는 동안 그 영역의 클릭은 게임에 전달되지 않는다.

### 2-2. 상태 표시
- 조준 중: 볼에서 골 방향으로 조준 화살표(`fx/fx-aim-arrow` 4프레임, 위쪽을 향한 그림을 광선 각도만큼 회전)와 점선, 골 평면에 **리티클**(`fx/fx-reticle`: 조준 중 프레임 0·1 맥동, 파워 중 2·3 금색; 착탄 예상 x, 조준 중 높이는 골문 절반). 파워 확정 중: 리티클이 `h`를 반영해 위아래 이동.
- 슛 후: 볼 트레일(꼬리 8점의 페이드 도형, 스윗스팟은 금색 + `env/ball-ring` 링). 결과 순간: 골 = 네트 리플·키퍼 `beaten`·플레이어 세리머니 A/B, 그 외 = 플레이어 `disappointed`. 카메라 흔들림(월드 레이어만)·히트스톱·콘페티·관중(스탠드 흔들기)은 P4 에서 구현 — 02 §7.
- **락커룸 게이트 근접**: 게이트가 열림 프레임으로 바뀌고 프롬프트 표시. `E`/`Enter`(프롬프트가 보일 때만) → `gate-open`·`transition-wipe` 소리 + 와이프(0.35s) → `LockerScene`. 200px 안에 처음 들어오면 `locker` 그룹을 백그라운드로 받기 시작(이미 받았으면 생략).

### 2-3. 캐릭터 변경 버튼
클릭 또는 `Tab` → `CharacterSelectScene` 오버레이(피치는 일시정지·유지). 취소하면 변경 없음.

- **입력**: ←→(행 안에서 순환) ↑↓(행 사이, 열 유지) 커서 이동(즉시 히어로 교체, `ui-cursor`), `Enter`/`Space` 확정, `Esc`/`Tab` 취소(`ui-back`), 마우스 hover=커서, 클릭=커서(`ui-click`), 400ms 안의 더블클릭=확정. 로딩 중에는 방향키/hover 가 커서를 옮기지 않고 Esc·돌아가기만 로딩을 포기시킨다. 커서가 이미 사용 중인 캐릭터면 확정은 그냥 닫는다(로드·리셋 없음).
- **확정 시**(P5 확정 순서): `ui-select` → `char:<id>` 그룹 로드(카드에 어둡게 + 볼 회전 로더) → **성공 후에만** `fc26-pitch-character` 저장 → `PitchScene.setCharacter()`(`hardReset()`: 볼·키퍼·플레이어·개인기·게이지·이펙트 리셋, **스코어는 유지**) → 이전 캐릭터의 `char:<prev>` 그룹 해제 → 닫힘. 실패(파일 오류·아틀라스 없음·예외)면 저장·교체 없이 현재 캐릭터 유지 + 카드 로더 제거 + 하단 문구 `불러오지 못했어요 · 현재 선수 유지`. (저장을 로드 뒤로 미룬 것은 03 원안 "저장 → 로드" 의 변경: 로드가 실패한 id 가 저장돼 다음 진입 때 다시 실패하는 것을 막기 위해서.)
- **초상화/히어로 로딩**: 오픈 시 `select` 그룹 지연 로딩, 끝나기 전에는 카드·히어로 자리에 맥동하는 스켈레톤 패널. 파일이 없거나 실패하면 테마색 블록 + 이름 첫 글자 폴백. 닫을 때 `select` 그룹 해제.
- **프리뷰(idle 1.2s → run 1.2s 반복)**: 커서 캐릭터의 아틀라스가 필요하다. 사용 중 캐릭터는 이미 로드돼 있고, 다른 캐릭터는 커서가 **0.25s 머문 뒤** `char:<id>` 를 받아 그린다(그 전까지 히어로만). 프리뷰용으로 받은 그룹은 커서가 떠나면 해제(동시에 하나) — 12명 아틀라스(약 5MB)를 한꺼번에 들고 있지 않는다. `assets.release` 는 다른 로드된 그룹이 같은 파일(초상화는 `select` 와 `char:<id>` 양쪽)을 가지면 그 파일을 지우지 않는다.
- **히어로 배치**: 히어로는 최대 높이 290 으로 맞춰 발끝 y=340(무대 위), 프리뷰 스프라이트는 x=164·발끝 y=452·배율 0.8. 사용자가 확인해 조정.
- **12명 순서**: 우왁굳, 재닌, 뽀린걸, 핑구, 문모모, 하치, 한결, 쥬멩이, 해파린, 빙밍, 다시바, 리냐.

## 8. 접근성/입력 보조
- 캔버스 `role="application"`, `aria-label="잔디동 피치 미니게임"`, 숨김 설명문(조작법).
- 대시보드 이동 링크는 항상 DOM에도 하나 존재(스크린리더/키보드용 `Skip to dashboard`, 화면 밖 배치).
- 색 대비: 텍스트는 어두운 판 위에 밝은 색 사용.
- **키보드 전용 흐름(P7 점검)**: 게임이 `Tab`(캐릭터 선택)·방향키·Space 를 가로채므로 캔버스에 포커스가 있으면 DOM `Skip to dashboard` 버튼에 키보드로 닿을 수 없다(포커스 트랩에 가까움). 그래서 **피치 화면에서 `Backspace` = 대시보드로 나가기**(`leave()`: `mode-switch` 소리 + 페이드)를 추가하고, 숨김 설명문(`#pitch-instructions`)과 화면 우하단 안내(`H 조작법 숨기기 · Backspace 대시보드`)에 적었다. 캐릭터 선택창·락커룸·스탯 화면은 각자 `Esc` 로 뒤로, 로딩이 느리면 `Enter`. 개인기·슛 중에도 `Backspace` 는 언제나 나간다(연습 게임이라 확인창 없음).
- `prefers-reduced-motion`: 카메라 흔들림·관중 흔들기·전환 와이프→페이드·**코너 플래그 흔들기**를 끈다(`host.reducedMotion()`).
- 스크린리더: `SceneHost.announce` 는 스탯 화면의 선택 축만 읽는다. 캐릭터 선택창·락커룸 프롬프트는 캔버스 텍스트만(백로그 — 필요하면 `announce` 호출 추가).
