# 11. 스탯 정의 — 포지션별 육각형 스탯의 이름·설명과 UI

락커룸 스탯 화면(`StatScene`, [03 §5](03-screens-and-ui.md#5-스탯-화면-statscene-락커룸-위-오버레이))의 육각형 6축과 우측 설명 패널에 들어갈 **실제 스탯 이름과 설명**을 확정한 문서다. 기존 계획(03 §5)은 라벨·설명을 전부 `???` 로 두었는데, **이름과 설명은 이 문서로 대체**한다. **능력치 숫자는 아직 정해지지 않았으므로 계속 `???`** 이다(COMING SOON 유지). 구현은 세션 **P6b**([10](10-session-prompts.md#세션-p6b--스탯-정의이름설명-반영))에서 끝났다(2026-09-25).

> **원천**: 사용자가 제공한 포지션별 스탯 정의 캡처 7장(공통 스탯 / ST·WF / CB / CM·CDM / FB / GK). 아래 "원문" 표기 문구는 캡처를 그대로 옮기되 오탈자·띄어쓰기만 정리했고, "정리" 표기 문구는 원문에 상위 설명이 없어 하위 항목을 요약해 만든 것이다(교체 가능). 구현된 문구는 `data/stats.ts` 가 최종본이며, `탈압박` 설명은 한 줄(320px)에 들어가도록 "압박 속에서 패스와 볼 컨트롤로 빠져나오는 능력" 으로 줄였다.

## 1. 확정 구조

| 항목 | 내용 |
| --- | --- |
| 스탯 수 | 포지션마다 **6개**(육각형 6축) |
| 필드 포지션(ST·WF·CB·FB·CM·CDM) | **공통 스탯 3개 + 포지션 고유 스탯 3개** |
| **GK** | **공통 스탯 없이 GK 고유 스탯 6개** |
| 감독(우왁굳 `MGR`) | 캡처에 정의가 없음 → **6축 모두 `???` 유지**(열린 결정 #7, README) |
| 축 순서 | 12시 방향부터 시계방향. 필드 포지션은 **공통 3개(위치선정 → 탈압박 → 패스) 다음에 고유 3개**(캡처 순서), 12시 = **위치선정** = 기본 선택 축. GK 는 캡처 순서 그대로(12시 = 위치 선정) |
| 능력치 숫자 | 미정 → 모든 축 값 `null` = **`???`**. 폴리곤은 60% 균일 플레이스홀더, `COMING SOON` 리본 유지 |
| 판정 표기 | `+` = 잘 수행했을 때 오르는 조건, `-` = 못했을 때 내려가는 조건(원문 표기). UI 에서는 초록 `+` / 코랄 `−` 로 구분 |

## 2. 데이터 모델 (`src/web/pitch/data/stats.ts` 확장)

기존 `StatAxis { id, label, description }` 과 API(`statSheetFor`, `axisLabel`, `axisDescription`, `STAT_PLACEHOLDER`, `isPlaceholderSheet`)는 **유지**하고 필드만 추가한다.

```ts
export type StatKind = "common" | "unique";

/** 하위 항목(예: 위치선정의 "수비 오프더 볼 위치선정", 탈압박의 "탈압박 패스"). */
export interface StatSub {
  title: string;                 // "탈압박 패스"
  text?: string;                 // 부가 설명("패스를 꼭 해야 하는 곳을 인지하는 능력")
  plus?: string;                 // 이 항목의 + 조건
  minus?: string;                // 이 항목의 − 조건
  children?: readonly string[];  // 칩으로 표시("리턴패스", "롱패스", "백패스")
}

export interface StatAxis {
  id: string;                    // "common-positioning", "st-goal-finishing"
  label: string;                 // 육각형 라벨·패널 제목("위치선정"). 6자 이내(라벨 판 72px)
  kind: StatKind;                // 공통/고유 → 색·태그
  description: string;           // 패널의 한 줄 설명(핵심 정의)
  plus?: string;                 // 판정 기준: 올라가는 조건
  minus?: string;                // 판정 기준: 내려가는 조건
  subs?: readonly StatSub[];     // 세부 항목(없으면 생략)
}
```

- `label`/`description` 이 `STAT_PLACEHOLDER`(`???`)이면 자리표시자 축(MGR). `isPlaceholderAxis(axis)` 헬퍼로 판별.
- 공통 스탯 3개는 **한 곳에서 정의해 6개 필드 포지션이 같은 객체를 공유**한다(문구 중복·불일치 방지). 같은 문구를 쓰는 고유 스탯도 공유한다: `골 결정력`(ST·WF·CM), `창조`(CB·FB·CDM 동일), `수비`(CB·FB 동일).
- `STAT_SHEETS` 는 여전히 `Record<PositionKey, StatSheet>`, `values` 는 전부 `null`(`isPlaceholderSheet` 참 → 리본 유지).
- 확정 숫자가 오면 `values` 만 채우면 되고 UI 는 수정 없이 폴리곤이 값을 따른다(기존 계약 유지).

## 3. 공통 스탯 3개 (필드 포지션 6종이 공유)

### 3-1. 위치선정 `common-positioning`
- **설명(원문 취지)**: 전술적으로 올바른 위치에 서 있는 능력.
- **+**: 전술적으로 위치했을 경우 · **−**: 위치하지 못했을 경우
- **세부 항목**
  1. 수비 오프더 볼 위치선정 — 수비 스탯이 있는 포지션은 제외 (원문 "수비 스탯 있을경우 제외")
  2. 공격 오프더 볼 위치선정
  3. 스위칭 판단

### 3-2. 탈압박 `common-press-escape`
- **설명(정리)**: 압박 속에서 패스와 볼 컨트롤로 빠져나오는 능력.
- **세부 항목**
  1. **탈압박 패스** — **+**: 탈압박 패스가 필요한 상황에서 이행 시 · **−**: 이행하지 못하거나 뺏길 시(유지 혹은 −) · 칩: `리턴패스` `롱패스` `백패스`
  2. **볼 컨트롤** — **+**: 볼을 빼앗기지 않을 경우 · **−**: 빼앗길 경우 · 칩: `볼키핑` `개인기` `드리블`

### 3-3. 패스 `common-passing`
- **설명(정리)**: 전술적으로 의미 있는 패스를 이행하는 능력.
- **+**: 전술적 패스 이행 시 · **−**: 이행하지 못할 시
- **세부 항목**
  1. **시야 (패스 판단)** — 패스를 꼭 해야 하는 곳을 인지하는 능력
  2. **패스 정확도** — 실제로 패스를 성공시키는 능력, 혹은 의미 있게 시도하는 능력

## 4. 포지션 고유 스탯 (필드 포지션 6종 × 3개)

라벨은 6자 이내, 설명은 원문.

| 포지션 | 순서 | id | 라벨 | 설명 | + | − |
| --- | --- | --- | --- | --- | --- | --- |
| ST·WF·CM | 4 | `unique-goal-finishing` | 골 결정력 | 넣어야 될 골을 넣는 능력 | 넣어야 될 골을 넣었을 시 | 못 넣었을 시 |
| ST | 5 | `st-holding` | 홀딩 판단 | 홀딩이 필요한 상황에서 홀딩하거나 홀딩 포지션을 잡는 판단 능력 | 홀딩해야 하는 상황에서 홀딩하거나 홀딩 포지션을 잡을 시 | 기타 유지 혹은 − |
| ST | 6 | `st-creation` | 창조 | 의외성 있는 플레이와 다양한 기술로 기점이 되거나 스스로 골 찬스를 만들어 내는 능력 | — | — |
| WF | 5 | `wf-dribble-break` | 돌파 | 상대 선수를 제치거나 벗기는 능력 | — | — |
| WF | 6 | `wf-creation` | 창조 | 의외성, 크리에이티브하게 상황을 스스로 만드는 능력. 엔드라인까지 쇄도하거나 측면에서 개인기 등으로 상황을 창출한다 | — | — |
| CB·FB | 4 | `unique-clearing` | 클리어 | 볼을 쓸데없이 끌지 않고 안전하게 클리어해야 하는 상황에 대한 정확한 판단 능력 | — | — |
| CB·FB·CDM | 5 | `unique-creation-defender` | 창조 | 의외성, 공격 가담 및 스위칭, 드리블 등으로 상황을 스스로 만드는 능력 | — | — |
| CB·FB | 6 | `unique-defending-back` | 수비 | 볼을 뺏어야 하는 상황에서 뺏을 수 있는 능력, 커버력 등 | — | — |
| CM | 5 | `cm-creation` | 창조 | 패스를 하거나 전진해야 하는 상황이 아닐 때를 파악하고 조율하는 능력, 스스로 상황을 만드는 능력 | — | — |
| CM | 6 | `cm-defending` | 수비 | 중미도 수비를 가담해야 할 상황 판단, 가로채기 능력 등 | — | — |
| CDM | 4 | `cdm-coordination` | 조율 | 포백으로 갈지, 전진할지, 왼쪽으로 갈지 오른쪽으로 돌릴지 판단하는 능력, 풀백 이용 능력 등 | — | — |
| CDM | 6 | `cdm-defending` | 수비 | 포백을 커버하는 능력, 수비 능력 등 | — | — |

- 각 포지션의 6축 순서 = 공통 3(위치선정, 탈압박, 패스) + 위 표에서 그 포지션이 속한 행을 **순서 열의 4→5→6** 로 나열.
  - ST: 골 결정력, 홀딩 판단, 창조 · WF: 골 결정력, 돌파, 창조 · CM: 골 결정력, 창조, 수비 · CDM: 조율, 창조, 수비 · CB/FB: 클리어, 창조, 수비.
- `골 결정력`(ST·WF·CM 공유), `창조`(CB·FB·CDM 공유: `unique-creation-defender`), `수비`(CB·FB 공유). 구현에서 같은 상수를 재사용한다.
- + / − 가 원문에 없는 스탯은 판정 기준 블록을 그리지 않는다(빈 칸 표시 금지).

- 6축 모두 `kind: "unique"`.

## 6. UI 설계 — 설명 패널

육각형(좌)은 그대로 두고, 우측 **설명 패널**(`STAT_DETAIL_PANEL` (512,104) 400×392, `ui/detail-panel` 을 1:1 로 그림)을 구조화해서 그린다. **실제 패널 아트 기준 좌표(패널 로컬, P6b 확정)**: 헤더 슬롯(x 93~309, y 27~66)에 제목, 어두운 본문 안쪽의 **내용 영역 = (40, 82) 320×204**(`DETAIL_CONTENT`), 그 아래 고정 하단 = 능력치 행 y 290(높이 14) + COMING SOON 리본 중심 y 328. 텍스트는 캔버스 Galmuri11(12px 본문 / 11px 부가 / 10px 라벨), 이미지는 기존 `ui/detail-panel`(9-slice)·`ui/axis-plate`·`ui/node-*` 재사용 + 캔버스 도형(신규 이미지 없음).

### 6-1. 패널 블록 (위→아래)

| # | 블록 | 내용 | 표현 |
| --- | --- | --- | --- |
| 1 | 머리줄(내용 영역 첫 줄) | 태그 칩 + `AXIS n/6` | 태그 칩 = 공통(청록 `#2be4ff`) / 포지션 고유(골드 `#ffd23f`) 라운드 칩 52×16, 글자 `공통`/`고유`(GK 는 `GK 고유`). 우측에 `AXIS n/6` 10px 청록 |

| 3 | 구분선 | | 2px 청록 반투명 |
| 4 | 설명 | `description` | 12px 흰색, 폭 320px 자동 줄바꿈(최대 4줄, 넘치면 `…`) |
| 5 | **판정 기준** | `plus`/`minus`(있을 때만) | 소제목 `판정 기준`(10px 청록) 아래 행 2개: `+` 초록(`#5cff9a`) 16×16 칩 + 조건 텍스트 / `−` 코랄(`#ff4d6d`) 칩 + 조건. 행 배경은 어두운 네이비 판(`#0f1330`) 1px 테두리, 텍스트 2줄까지 |
| 6 | **세부 항목** | `subs`(있을 때만) | 소제목 `세부 항목`. 항목마다 골드 ■ 불릿 + 제목(12px) → 부가 설명(11px 회색 `#b9b9e6`, 줄바꿈) → `+`/`−` 미니 행(있으면) → 자식은 **칩**(청록 테두리 라운드 칩, 가로로 흐르며 줄바꿈) |

| 8 | COMING SOON | 기존 `drawRibbon` | 패널 하단 리본(기존 그대로) |

- **레이아웃 함수**: `ui/statDetail.ts` 의 순수 함수 `layoutStatDetail(axis, availableWidth, measure)` 가 `{blocks, height}`(블록 = head·divider·desc·criteria·subs, 각 y·높이·줄 목록; 제목은 헤더 슬롯이라 블록에 없음, 자리표시자 축은 desc 만)를 반환하고 `StatScene` 은 그리기만 한다. 줄바꿈은 Galmuri11 이 한글 1글자 = 폰트 크기 폭이므로 글자 단위로 자르되 문장 부호·공백에서 우선 끊는다(`wrapText(text, maxWidth, measure)`). `measure` 를 주입해 테스트에서 가짜 측정기(글자당 size px)를 쓴다.
- **높이 예산(P6b 확정)**: 원안의 316px 는 패널 아트를 무시한 값이었다. 실제 아트의 어두운 본문(약 y 76~352)에서 능력치 행+리본을 빼면 콘텐츠 영역은 **204px**. 글자당 size px 인 가짜 측정기(한글 전각, 실제 Galmuri11 과 같은 최악 가정)로 42개 전 축의 총 높이가 ≤ 204px 임을 테스트가 보장한다(최대 = `위치선정` 195px, `탈압박` 190px). 실제 폰트가 더 좁아 더 짧게 나오며, 그래도 넘치면 **스크롤**: 콘텐츠 영역 클립 + 하단 페이드 + `▼`(위로 스크롤했으면 `▲`), **마우스 휠·`↑↓`**(20px 씩)로 스크롤 — 축 선택은 ←→/Tab 이라 충돌 없음(**원래 `↑↓` 도 축 순환이었으나 스크롤로 바꿨다**), 축이 바뀌면 스크롤 0, 상한 = 내용−영역으로 클램프. `Scene.onWheel` + `SceneManager.wheel` + PitchEntry 의 canvas `wheel` 리스너(passive:false)가 연결한다.
- **전환**: 축이 바뀔 때 패널 제목·내용 0.12s 페이드 + 8px 슬라이드(`prefers-reduced-motion` 이면 즉시).
- **다시 그리기 비용**: 축이 바뀔 때만 레이아웃 재계산(캐시), 프레임마다 재계산 금지.
