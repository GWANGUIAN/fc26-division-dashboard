# 02. 게임플레이 사양 — 조작, 물리, 슛, 개인기, 골키퍼 AI, 판정

> 수치의 원천 코드는 `game/tuning.ts`(`MOVE`·`DRIBBLE`·`PLAY_AREA`·`SPAWN`·`GOAL`·`GOAL_MOUTH`·`GOAL_SCREEN`·`SHOT`·`KEEPER`·`MATCH`·`DUST`·`SKILLS`·`STYLE`·`JUICE`)이며 §2~§6 표와 항상 같아야 한다(P4 완료 시점 일치 확인). 이 문서의 수치는 **튜닝값**이다. 구현 세션(P2~P4)에서 플레이하며 바꾸고, 바꾸면 `src/web/pitch/game/tuning.ts`와 이 문서 표를 같이 고친다([README 변경 전파 프로토콜](README.md#변경-전파-프로토콜)). 좌표는 논리 960×540 기준 픽셀([03](03-screens-and-ui.md) 참고).

## 3. 드리블

볼 상태: `carried`(소유) / `loose`(루즈) / `shot`(슛 비행) / `dead`(득점·아웃 후 대기).

- **carried**: 볼은 발 앞 목표점 `foot + facingDir × 28px`(y 성분은 ×0.75, 플레이 영역으로 클램프)을 스프링으로 따라간다(`k=18`, 감쇠비 ζ=1). **플레이어 이동 프레임 기준 스프링**: `a = k²(target − ball) − 2ζk(v_ball − v_player)` — 일정한 속도로 달릴 땐 볼이 목표점에 정확히 머물고(달리기 ≈ 28px), 방향을 바꾸거나 멈추면 볼이 관성으로 잠깐 남아 **터치가 보인다**. 이 세션에서 스프링에 감쇠비(ζ)를 추가했다(원안은 k 만 지정).
- **스프린트**: 목표 거리 44px, `k=9`, **ζ=0.15**(저감쇠) → 볼이 몸에서 멀어지고 방향 전환 뒤 앞뒤로 출렁인다. 볼이 발에서 **90px 이상** 벌어지면 `loose`로 전환(소유 상실). 튜닝 결과(고정 스텝 시뮬레이션): 직선 스프린트 최대 약 60~70px(안전), 정지 상태에서 스프린트 시작 약 68px, **한 방향 약 0.35~0.4s 간격으로 좌우 꺾기를 반복하면 1초 안팎에 90px 초과 → loose**. 일반 달리기의 꺾기는 최대 약 32px로 안전.
- **loose**: 마찰 `4.0/s`(`v × e^(−4t)`, 속도 < 4 이면 정지)로 감속하며 굴러간다(소유를 잃는 순간의 속도를 이어받음). 플레이어가 **20px 이내**로 접근하면 다시 `carried`(0.15s 트래핑 연출, 볼이 살짝 커졌다 줄어듦).
- **경계**: `carried` 볼은 플레이 영역 안에 고정된다(벽에 붙어 달려도 소유 유지). `loose` 볼이 플레이 영역 밖으로 나가면 `dead`(그 자리에 정지, 반투명) → 0.6s 후 **볼만** 스폰(480,440)으로 리셋되어 `loose` 로 놓인다(플레이어가 20px 안이면 즉시 재소유). **R 키**는 플레이어·볼·먼지를 모두 스폰으로 리셋한다.
- **볼 애니메이션**: `env/ball-spin`(8프레임)은 굴러간 거리에 비례(0.16프레임/px, 방향 부호 = 지배 축의 속도 부호), 그림자 `env/ball-shadow`는 볼 발밑(지면 좌표)에 항상 깔린다.
- 슛 진입 조건: `carried`이고 볼에서 골문 중심(480,150)까지 거리 **≤ 520px**(`SHOOT_MAX_DISTANCE`). 초과 시 "TOO FAR" 0.7s 흔들림 + `pitch-too-far` 소리(상태 변화 없음).
- **shot**(P3): `launchBall` 이 스크립트 비행을 시작한다 — 지면 접점 (x, y)는 시작점 → (480+tx, 화면 골면 118)로 선형 이동하고 `z`(화면 px)는 §4 아치. 골 평면 도달(`ballArrived`) 시 match 가 결과를 정하고 `releaseBall` 로 **자유 비행**(중력 900 px/s², 바운스 0.5, 지면 마찰 3/s)으로 넘긴다. 비행 중 플레이어는 정지(입력 0)하고 볼은 `loose`/`dead` 로 바뀌지 않는다. 결과 시퀀스가 끝나면 볼·플레이어·키퍼가 스폰으로 리셋된다.

## 4. 슛

**3단계**(모두 `Space`), 진행 중 플레이어는 정지(씬이 `stepPlayer` 입력을 0 으로 넣음. 아케이드식 "타임 슬로"는 없음). 상태기계 `ShotPhase = idle → aim → power → released` (`game/shot.ts`).

1. **시작**(`idle→aim`): `Space`. `carried` 이고 거리 ≤ 520 일 때만([§3](#3-드리블)). 플레이어가 골(위)을 본다. 골대 위에 **조준 화살표 + 조준 바**가 나타나고 **화살표가 좌우로 왕복**한다.
   - 삼각파(`aimWave`), 주기 **1.1s**, 시작은 중앙에서 오른쪽으로. 광선 각도는 "골 포스트 ± 오버슈트 12%·W(28.8px)" 양 끝 광선 사이를 **각도로 선형 보간**(`aimRay`) — 화살표가 고르게 회전한다. 스폰(480,440)에서는 스윕 중앙이 정확히 골문 중심.
2. **조준 확정**(`aim→power`): `Space` → 화살표 정지, **파워 게이지**(`powerWave`)가 0→100→0 삼각파(주기 **1.8s**, 시작 0)로 움직인다.
3. **파워 확정**(`power→released`): `Space` → 킥. 스윗스팟 구간 **78~92**(`SHOT.sweetMin/sweetMax`, 게이지에 금색 표시).
   - 취소: `Esc`(단계 1~2에서), 각 단계 **3s 타임아웃**(단계가 바뀌면 타이머 재시작)이면 `idle`로(볼 유지). 킥 이후는 취소 불가, `R` 은 전부 리셋.

**착탄 계산** (골 평면, `computeShot`):

| 값 | 공식 |
| --- | --- |
| 목표 x 오프셋 `tx` | `aimRay` 가 골 라인과 만나는 x − 480 + 지터 |
| 목표 높이 `h` | `h = goalH × (0.12 + 0.88 × (p/100)^1.2)`, `p>92`면 `h`에 추가 `+ (p−92) × 2.4`(크로스바 위로 뜸) |
| 비행 속도 `v` | `v = lerp(420, 1100, p/100)` px/s |
| 비행 시간 `T` | `dist(ball, (480+tx, 150)) / v` (`ShotFlight.time`) |
| 지터 σ | `σ = 0.06·W × (1 + |p−85|/40) × (0.8 + dist/500) × (1 + |angleDeg|/60)`, 정규분포(`angleDeg` = 광선의 수직 기준 각도) |
| 스윗스팟 보너스 | `p ∈ [78,92]`: 지터 ×0.6, 볼에 금색 링 이펙트·금색 트레일 |
| 시각 z(t) | `z(t) = h·s + 0.16·dist·(p/100)·4·s(1−s)` (s = t/T; **원안에 파워 계수 `p/100` 을 추가** — 원안 그대로면 약한 슛도 중간에 0.16·dist(≈50px) 떠서 "땅볼에 가까움" 서술과 충돌) |

- 파워 낮음(<40): 땅볼에 가깝고 느림 → 쉬운 선방. 파워 높음: 빠르고 높음 + 지터 증가 = 리스크/보상.
- **판정 순서**(`classifyShot`, 포스트·바 허용 오차 6px):
  1. `h > 86` → `|tx| > 126` 이면 **WIDE**, 아니면 **OVER**
  2. `| |tx| − 120 | ≤ 6` → **POST**(높이 무관, 안쪽·바깥쪽 모두)
  3. `|tx| > 120` → **WIDE**
  4. `|h − 80| ≤ 6` → **BAR**(반동으로 튕겨 나감, 득점 아님)
  5. 그 외 **ON TARGET** → 키퍼 판정([§6](#6-골키퍼-ai))
- `p > 92`는 `p≈93.5~96`에서 BAR, 그 위는 OVER 라 사실상 "너무 세게 차면 뜬다".
- 화면 표현: 볼은 지면 좌표(x, y: 시작 → 화면 골면 118)에 그림자를, 그 위 `z × 74/80` px 에 스프라이트를 그린다. 조준 중 리티클은 착탄 예상 x(높이는 골문 절반), 파워 중에는 파워에 따른 `h` 로 위아래 이동.

## 5. 개인기와 스타일 게이지

개인기는 **골키퍼를 속이는 버프**를 주는 것이 게임적 의미다(수비수가 없으므로).

| 키 | 개인기 | 클립 | 지속 | 이동 | 스타일 |
| --- | --- | --- | --- | --- | --- |
| Z | 스텝오버 | `skill_stepover` | 0.45s | 전방 48px | +25 |
| X | 룰렛(마르세유) | `skill_roulette` | 0.55s | 전방 60px, 방향 유지 | +35 |
| C | 레인보우 플릭 | `skill_rainbow` | 0.70s | 전방 72px(점프) | +45 |
| V | 엘라스티코 | `skill_elastico` | 0.55s | 전방 56px | +50 |

- 조건: `carried` 상태(볼 소유). 소유가 아니면 **헛스윙**(애니메이션만 — 이동·스타일·체인 없음, `볼이 없어요` 라벨).
- 쿨다운 0.5s(**개인기가 끝난 시점부터** 센다). 개인기 중에는 이동 입력 무시(스크립트 이동), **마지막 0.15s는 슛 캔슬 가능**: 그 창에서 Space 는 개인기를 끝내고 `tryShotPress` 를 호출한다(볼이 발에 있고 골문 520px 이내일 때만 — 아니면 개인기가 계속된다). 창 밖의 Space 는 무시.
- 방향: 진행 방향(`facing`)으로 실행. 위쪽 성분이 지배적이면 `up` 클립, 그 외 `side`(왼쪽은 미러). 아래쪽을 볼 때도 전용 프레임이 없어 `side` 를 재생.
- 이동: `easeInOutSine` 으로 `move` px 를 `duration` 동안 미끄러짐(시작·끝 속도 0, y 성분은 `MOVE.yFactor`), 플레이어 속도는 매 스텝의 변위/dt 로 넣어 볼 스프링이 이동 프레임을 따라간다. 4프레임은 지속시간에 고르게 분배(fps 가 아니라 진행률). 레인보우만 `hop` 22px 점프(볼도 1.3배로 같이 뜸).
- 개인기마다 흔적이 다르다: 스텝오버=먼지, 룰렛=`fx-grass`, 레인보우=`fx-star`(머리 위), 엘라스티코=`fx-speed`. 시작 시 `<이름> +<획득량> [x1.5|x0.5]` 라벨이 플레이어 위로 떠오른다(0.9s).
- **체인 콤보**: 직전 성공 개인기가 **끝난 뒤** 2.0s 안에 서로 다른 개인기를 이으면 스타일 획득 ×1.5(같은 개인기 반복은 ×0.5). 콤보 핍(최대 5개)은 다른 개인기를 이을 때마다 +1, 같은 개인기는 유지, 창이 지나면 0(다음 성공은 1부터). 헛스윙은 체인에 영향 없음.
- **스타일 게이지**(0~100): 개인기 **시작 순간**에 획득량이 더해진다. 마지막 획득 후 2.0s 뒤부터 15/s 로 감소. 슛을 조준·비행 중일 때(`shot.phase ≠ idle` 또는 `match.phase ≠ play`)는 감소가 멈춘다(조준이 스타일을 깎지 않게).

| 스타일 | 슛 시 효과(골키퍼 "속임") |
| --- | --- |
| ≥ 50 (Tier 1) | 골키퍼 반응 +0.10s, 다이브 방향 예측 오차 ×1.25 (`KEEPER.tierReact/tierPredErr`) |
| ≥ 80 (Tier 2) | 골키퍼 반응 +0.20s, 예측 오차 ×1.5, **완전 속임 8%**(`tierFooled`, 그 슛은 반드시 뚫림) |

- **연결(P4 완료)**: `PitchScene.styleTier()` 가 게이지 값(≥50 → 1, ≥80 → 2)을 돌려주고 `kick()` 이 그 값을 `planSave(kick, keeperX, tier, ...)` 에 넘긴다. 디버그 패널의 T 키로 Tier 를 올려 둔 동안은 그 값이 우선. 효과 크기는 [§6](#6-골키퍼-ai)의 측정값 참고(표 평균 −13.6 / −28.4pt).
- **소비**: 킥 순간 `kick()` 이 `styleTier()` 를 읽은 직후 `consumeStyle` 로 게이지·콤보·체인을 0 으로 리셋(취소한 조준은 소비하지 않음). 게이지는 HUD 우측 세로 바([03](03-screens-and-ui.md)).
- **Tier 콜아웃**: 개인기로 Tier 1 을 넘으면 `STYLE!`(`ui/banner-style`), Tier 2 를 넘으면 `PERFECT!`(`ui/banner-perfect`) 배너 1.1s + `pitch-style-tier` + 머리 위 `fx-star`.
- 슬라이드 이동 중 경계를 넘지 않도록 위치를 `PLAY_AREA` 로 클램프(벽 쪽 속도 성분은 0).

## 6. 골키퍼 AI

**상태기계**(`game/keeper.ts`): `KeeperPhase = ready → track → dive → resolve → recover`

- **ready/track(포지셔닝)**: 볼 x를 따라 좌우 이동. `targetX = 480 + clamp((ball.x − 480) × 0.35, −60, +60)`(`keeperTargetX`, 각을 좁힘), 최대 속도 180 px/s, 가속 900 px/s². 목표에 닿으면 `ready`, 움직이는 동안 `track`(shuffle 클립). 0.25s 마다 5% 확률로 0.3s 머뭇거림(사람 같은 페이크) — 킥 시점에 머뭇거림이 남아 있으면 반응 시간에 더해진다.
- **dive**: 킥 순간 `planSave` 가 **결과 전체를 한 번에 결정**하고(테스트 가능), 씬은 그 계획을 재생한다. `reactDelay` 동안 제자리, 이후 `max(T − reactDelay, 0.25s)` 동안 `easeOut` 으로 `endX` 까지 이동(dive 클립 프레임 = 진행률). 이동이 16px 미만이면 `stay`(제자리 캐치/펀칭/발 세이브 클립).
- **resolve**: 볼이 골 평면에 닿는 순간 씬이 `resolveKeeper(outcome)` 호출. dive 였다면 0.4s 동안 마지막 다이브 프레임 → GOAL `beaten`(1.0s 유지) · SAVE `save_celebrate` · 그 외 `ready`. `stay` 세이브는 `catch`/`punch`/`foot_deflect` 0.5s 후 `save_celebrate`.
- **recover**: resolve 1.0s 뒤 중앙으로 걸어 돌아옴(셔플 클립). 리셋 시 즉시 중앙.

**판정 모델**(`planSave`, 모든 난수는 주입된 `Rng`):

1. **반응**: `reactDelay = D.react + tierReact[tier] + 남은 머뭇거림`.
2. **예측**: `tx' = tx + N(0, σ_pred)`, `h' = h + N(0, 0.2·goalH)`, `σ_pred = D.predErr × W × tierPredErr[tier]`. 방향 = `sign(tx' − keeperX)`, 높이 = `h' > 0.5·goalH ? high : low`.
3. **도달**: `t_avail = max(0, T − reactDelay)`, `R = min(D.diveSpeed × t_avail, D.maxReach)`, 스윗스팟이면 `R × D.sweetReach`, 그 뒤 `R = R × max(0.4, 1 + N(0, D.reachSpread)) + D.bodyReach`(몸통·팔 길이 고정분).
4. **판정**(모두 충족해야 선방): ① `|tx − keeperX| ≤ R` ② 방향 일치(단 `|tx − keeperX| ≤ D.centerZone` 이면 방향 무관) ③ 높이 매칭: low 다이브는 `h ≤ 0.55·goalH`, high 다이브는 `h ≥ 0.35·goalH` ④ Tier 2 "완전 속임"이 아님.
5. **종류**: `|tx−keeperX| ≤ R − 25` & `p < 60` → **CATCH**, 그 외 `p < 85` → **PUNCH**, 그 이상 → **DEFLECT**(50% 리바운드 = 득점 아님·`SAVE`, 50%는 손끝을 스쳐 골 = `grazed` GOAL).
6. 다이브 끝점: 선방/스침이면 볼 쪽(최대 R), 실점이면 예측 방향으로 `max(0.6·거리, 30px)`.

**난이도 변수 D (P3 최종값, `KEEPER`)**: `react=0.20s`, `diveSpeed=328px/s`, `maxReach=92px`, `predErr=0.08`, `bodyReach=13.5px`, `reachSpread=0.23`, `centerZone=30px`, `sweetReach=0.95`, `tierFooled=[0,0,0.08]`.
- 초기값(`react 0.22 / diveSpeed 520 / maxReach 130 / predErr 0.16`)에 원 공식 그대로 돌리면 표와 최대 28pt 어긋났다(중앙·스윗스팟 37% vs 65% 등: 도달 시간이 0.1~0.15s 뿐인 스윗스팟은 다이브 속도로는 못 막고, 반대로 낮은 파워는 도달 상한에 막혀 코너까지 다 막았다). 그래서 **몸통 고정 도달(`bodyReach`)·도달 편차(`reachSpread`)·스윗 도달 배율(`sweetReach`)·방향 무관 반경(`centerZone`)** 을 D 에 추가하고 4개 원 변수를 다시 맞췄다. 난이도 3단계(쉬움/보통/어려움)는 P7에서 검토(스킨 색으로 표시).

**목표 선방률 표** (기본 난이도, 튜닝의 정답지). 구역: 중앙 `|tx|/(W/2) < 0.3`, 중간 0.3~0.7, 코너 0.7~0.95(그 위는 포스트 구간). 파워 밴드: 낮음 0~40, 중간 41~77, 스윗스팟 78~92:

| 구역 \ 파워 | 낮음 | 중간 | 스윗스팟 |
| --- | --- | --- | --- |
| 중앙 | 90% | 80% | **60%** |
| 중간 | 75% | 55% | 30% |
| 코너 | 55% | 35% | 8% |

- **표 변경(P3)**: 중앙×스윗스팟 65% → **60%**. 근거: 스윗스팟 볼은 도달 시간이 0.1~0.15s 라 골키퍼의 기본 위치 편차(±49px)가 그대로 드러나 중앙이라도 60%가 상한이었고, 65%를 맞추려고 도달을 늘리면 중간·코너 셀이 함께 올라 나머지 8셀이 어긋났다(9셀 최대 오차 5.7pt → 4.8pt). 나머지 8셀은 원안 그대로.
- **측정값**(20,000회/셀, seed 20260925, Tier 0): 중앙 90.9/80.3/58.7 · 중간 79.1/59.7/34.8 · 코너 50.2/30.2/10.9, 평균 55.0%. 표에 가장 먼저 어긋나는 셀은 코너×낮음(−4.8)·중간×중간(+4.7)·중간×낮음(+4.1).
- **Monte Carlo 시나리오**(`game/montecarlo.ts`, `MC_SCENARIO`): 거리 250~450 균등, 슈터 x = 480 ± 140 균등(키퍼는 0.35 팔로우로 서 있음), tx 는 구역 안 균등(좌우 무작위), 파워는 밴드 안 균등, 머뭇거림 5% 포함.
- **스타일 Tier**: 반응·예측 오차만으로 표 평균이 Tier 1 −13.6pt(목표 −15), Tier 2 −26.0pt 라 Tier 2 에 완전 속임 8%를 더해 **−28.4pt**(목표 −30). 원안의 "Tier 2 선방률 −15pt 추가"(§5)와 "Tier1 −15, Tier2 −30"(§6)이 서로 달라 **측정 평균 기준**으로 통일했다(하한 0%).
- `p > 92`는 선방이 아니라 OVER/BAR(대부분 빗나감).
- **검증**: `keeper.test.ts`에서 각 셀 20,000회 Monte Carlo(시드 고정) 결과가 목표 ±6pt 안이어야 통과. 참고 시뮬레이션(스폰 주변 다양한 위치): 파워 40~100·조준 무작위 캐주얼 유저 **골 43% · 선방 28% · 빗나감 18% · 포스트/바 10%**, 스윗스팟(70~95)을 노리는 유저 골 58%, 코너를 노리는 숙련 유저 골 65~81%. 목표(평균 45~55%, 숙련 70%+)에 부합.

## 8. 개발용 디버그
`?pitchDebug=1`(`scenes/pitchDebug.ts`, 쿼리가 있을 때만 켜짐 — **배포 빌드에서도 동작**해서 배포 후 튜닝을 확인할 수 있고, 쿼리가 없으면 일반 진입에 아무 영향 없음): 히트박스(플레이어·볼 반경 20·키퍼)·골평면(청록 사각형 + 금색 골 라인)·키퍼 도달 반경(주황 막대, 킥 후에는 그 다이브의 실제 R 과 끝점 초록/빨강 점)·볼 높이선을 그리고, 튜닝 패널을 좌측에 표시한다.

| 키 | 동작 |
| --- | --- |
| `B` | 패널 켜기/끄기 |
| `[` `]` | 조절할 값 선택(react · diveSpeed · maxReach · predErr · bodyReach · reachSpread · sweetMin · sweetMax) |
| `-` `=` | 선택한 값 감소/증가(실시간 반영, 저장 안 함) |
| `1` `2` `3` `4` `5` | 다음 슛 결과 강제 GOAL / SAVE / POST / BAR / MISS(같은 키 다시 = 해제) |
| `T` | 스타일 Tier 0→1→2 (올려 둔 동안은 게이지보다 우선. 0 으로 돌리면 게이지 값이 다시 쓰임) |
| `0` | Monte Carlo 선방률 표(Tier 0·1·2, 각 셀 20,000회, 괄호 = 목표)를 콘솔에 출력 |

패널 하단에 마지막 슛의 파워·tx(조준점/지터 σ)·h·비행 시간·판정·키퍼 결과가 표시된다. 튜닝 값은 씬의 복사본(`shotTuning`·`keeperTuning`)만 바꾸므로 새로고침하면 `tuning.ts` 기본값으로 돌아간다 — 마음에 드는 값은 `tuning.ts` 와 §6 에 옮긴다.
