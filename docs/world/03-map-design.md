# 03. 맵 설계 — 잔디동 월드

오버월드(80×60 타일)와 실내 19곳의 **구역·좌표·충돌·트리거·데이터 스키마**를 정한다. 규격은 [01](01-concept-and-architecture.md), 누가 어디에 있는지·무슨 미션인지는 [02](02-story-and-missions.md), 이미지 프롬프트는 [05](05-art-world.md).

## 1. 좌표계와 규칙

- 좌표는 **타일 (tx, ty)**, 원점은 좌상단, 1타일=32px. 픽셀 좌표는 `x = tx*32`, 엔티티 위치는 **발끝 중앙** 기준.
- 오버월드 `80×60`(2560×1920px). 가장자리 2타일은 두꺼운 숲/절벽 띠로 막는다(JSON `walkable`이 걷기 가능 영역을 `[2, 2, 76, 56]`으로 정하고, 띠 위에는 나무를 촘촘히 심는다).
- 좌표표의 사각형은 `x0–x1, y0–y1`(양끝 포함) 타일 범위. 아래 개략도는 **2×2타일=1글자** 축소본이라 오차가 있으며, **좌표표가 기준**이다.

> **S2에서 고친 점**: ① 원래 표는 지구 사이에 빈 줄·열(17행, 53열)이 있었고 중앙(20–55)이 구름·봄(–24)과 겹쳤다. 빈 곳이 없도록 구름·룬 `y 2–17`, 봄·서리 `y 18–43`, 상점가 `x 28–53`으로 한 칸씩 넓혔다. ② 겹치는 곳(20–24열)은 **JSON `zones` 배열 순서가 우선순위(먼저 맞는 지구가 이김)**이고 `z-center`가 맨 앞이다(훈련장·서쪽 큰길이 중앙 소속이 되도록). ③ 실제 지면은 이 시트 그대로다. `z-rune`은 `terrain-cloud`의 룬 슬랩·이끼 돌, `z-frost`의 호수는 `terrain-water`. 물·공업·제초 시트는 시든 변형이 없어 **lush 그대로** 쓴다.

- **복원(색 회복)**: 전역 진행도 `s = shards/10`. 지구별 복원값 `restore(z) = 0.6*s + 0.4*zoneDone(z)`(해당 지구 멤버 미션 완료 비율). 제초동 구역은 엔딩 전 항상 시든 상태로 고정, 엔딩 후 별도 컷으로 초록 복원. 지면 청크는 lush/withered 2벌 알파 블렌드, 소품(나무·덤불·꽃)은 lush/withered 이미지를 `restore` 임계로 교체.
- 지구 진입 시 토스트: "🌸 봄 정원" 형태(이모지 대신 코드 아이콘 권장), BGM 크로스페이드.

- 조사 영역은 타일 중앙 기준 기본 64×48px(`size`로 조절). 플레이어가 바라보는 방향 28px 앞 상자가 영역에 닿으면 `E` 프롬프트가 뜬다.

## 10. 맵 데이터 스키마

`data/maps/overworld.json`, `data/maps/interiors/<id>.json`(타입은 `types.ts`의 `OverworldMapData`/`InteriorMapData`). 오버월드 JSON은 **`node scripts/build-world-map.mjs`가 이 문서의 존/길/건물 표에서 처음 생성**했고(`--ascii`로 글자 그림 미리보기, `--terrain-only`로 지면만 다시 생성), 이후 손으로 다듬는다. 좌표 단위가 필드마다 다르니 주의한다: **`rect`(zones·buildings) = `[x0, y0, x1, y1]` 타일, 양끝 포함**, `door`·`triggers[].rect`·`npcs[].wander`·`walkable` = **`[x, y, w, h]` 타일**, `collision` = **`[x, y, w, h]` px**, `props` = 발끝 px.

```jsonc
{
  "id": "overworld",
  "size": [80, 60],
  "tile": 32,
  "walkable": [2, 2, 76, 56],            // 타일 [x, y, w, h]. 바깥 2타일은 숲 띠(못 들어감)
  "spawn": [40, 17],                     // 디버그 텔레포트·세이브 복구용 기본 위치(타일)
  "legend": { "g": "core/grass-a", "s": "core/path-dirt-a", ... },   // 글자 → "<시트>/<슬롯>"
  "terrainRows": ["gggg...", "... (60행 × 80글자)"],
  "zones": [ { "id": "z-spring", "name": "봄 정원", "rect": [2, 18, 24, 43], "tint": "#ffb3d6", "particles": "petals", "bgm": "region-spring" } ],  // 앞선 항목이 우선
  "props": [ { "prop": "tree-oak", "x": 320, "y": 480 } ],                 // px, 발끝 기준
  "buildings": [ { "id": "clubhouse", "rect": [34, 6, 45, 13], "door": [39, 13, 2, 1], "interior": "clubhouse-lobby" } ],
  "collision": [ [x, y, w, h] ],         // px. 건물(문 칸 제외)·깊은 물·제초동 울타리. 소품 충돌은 propDefs 발자국에서 자동
  "npcs": [ { "cast": "elder", "tile": [36, 21], "ai": "stay" },
            { "cast": "kid", "tile": [44, 22], "ai": "wander", "wander": [33, 18, 15, 8] } ],
  "triggers": [ { "type": "door", "rect": [39, 13, 2, 1], "to": { "scene": "interior:clubhouse-lobby", "tile": [10, 10], "facing": "up" } } ],
  "examine": [ { "id": "sign-plaza", "tile": [35, 25], "text": "…", "size": [48, 40] } ]
}
```

```jsonc
// interiors/<id>.json
{
  "id": "house-doormomo", "image": "interiors/int-house-doormomo", "size": [20, 12],
  "spawn": [10, 10], "exitTo": { "scene": "overworld", "tile": [67, 13] },   // 문 오른쪽 칸 바로 아래(NPC가 왼쪽 칸 앞에 서 있음)
  "collision": [[0,0,640,118],[0,118,46,266], ...],                          // px, 이미지 좌표(640×384)
  "examine": [ { "tile": [10, 3], "text": "빽빽한 화살표들이 그려져 있다." } ],
  "npcs": [ { "cast": "doormomo", "tile": [10, 7], "ai": "stay", "when": "mission-completed:m-doormomo-sum10" } ],
  "triggers": [ { "type": "door", "rect": [9, 11, 2, 1], "to": { "scene": "overworld", "tile": [67, 13], "facing": "down" } } ]
}
```

- `props`는 `data/propDefs.ts`(스프라이트 크기 `w×h`, 실제로 보이는 크기 `content`, 발자국 `foot[]`, `aboveFrom`, `decal`, `withered`)를 참조한다. 소품 id는 [05 §소품 시트](05-art-world.md#2-소품-시트-11장)의 파일명과 같다. 스프라이트는 **하단 중앙이 앵커**(발끝)다.
- `when`이 있는 NPC는 S3에서 미션 상태를 평가하기 전까지 스폰하지 않는다(`mission-completed:<id>`, `flag:<name>`, `not:flag:<name>` 형식 예정).
- 문 트리거는 `type: "door"`만 S2에 구현됐다. `pickup`·`goal`·`zone`·`checkpoint` 등은 S3 이후에 스키마에 추가한다(지구 토스트는 `zones`로 처리해서 `zone` 트리거가 필요 없다).
- **무결성 테스트(`data/maps/mapIntegrity.test.ts`)**: 모든 `door.to.scene` 존재 + 도착 지점이 충돌 밖, 건물 문이 스프라이트의 마지막 줄에 있고 실내 `exitTo`가 문 앞 칸과 일치, 모든 실내에 아래 문·열린 스폰, `npcs.cast` ∈ 캐스트·서 있는 자리가 열려 있음·`worldCast.spawn`과 일치, `props.prop` ∈ propDefs, 참조 이미지(소품·건물·실내·아틀라스·지면 시트) 존재, 모든 걷기 가능 타일이 지구에 속함, 그리고 **스폰에서 걸어서 모든 문 앞과 NPC까지 닿을 수 있는지(도달성)**. 봉쇄된 제초동 구역과 공장 문은 "닿지 않아야 한다"를 검사한다.

## 11. 충돌·정렬 규칙 요약

- 건물: **보이는 스프라이트 전체가 벽, 문 칸만 통과**(S2 결정, [§4](#4-랜드마크건물-좌표표)). 건물에는 `above`가 필요 없고 y-sort(`sortY` = 하단 y)만 쓴다.
- 나무: 줄기 발치만 충돌(표의 16×12 등). **`aboveFrom`(S2 결정)**: 스프라이트 바닥에서 그 px보다 위쪽 부분은 플레이어·NPC를 다 그린 뒤 한 번 더 그려 머리 위를 덮는다. 기본값은 나무 40px(큰 참나무 48px) = 줄기 높이, 아치 48–64px = 기둥 높이(`sakura-arch` 64, `flower-arch` 56, `stone-arch` 48). 그 밖의 소품은 `above` 없이 y-sort만. 값은 `propDefs.ts`에서 소품별로 고친다.
- 울타리·물·벽은 사각형 충돌. 깊은 물만 막고 얕은 물·모래는 통행 가능. 다리/데크는 충돌 없음(난간 art가 없어 깊은 물 충돌이 난간 역할).
- 소품 발자국은 05 표 값을 옮기되 **보이는 그림보다 크면 그림 크기로 줄였다**(울타리·기둥류 29개, 목록은 `propDefs.ts` 주석과 [09 §11](09-asset-checklist.md#11-s2-소품-충돌-크기-대조-2026-09-19)).
- y-sort 키: 발 y(`sortY = y`). 바닥 장식(`decal`: 문 매트·꽃잎 더미·피크닉 담요 등)은 정렬 제외로 가장 아래에 그린다. 지면은 청크 캐시(512px) 위 lush/withered 2벌을 지구 복원값으로 크로스페이드한다.
- NPC 위치가 플레이어 이동 경로를 완전히 막지 않도록 좁은 통로에는 `stay` NPC를 두지 않는다.
